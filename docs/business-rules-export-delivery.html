📋 Business Rules – Export Note & Delivery Management

Module ID Detail Rule
Export Note Management
(EXP)		 Hidden system logic When a store order has status CONSOLIDATED and all required products have sufficient available stock, the order is eligible for export.
BR-EXP-001 The system automatically applies FEFO (First Expired, First Out) when selecting batches for export — batches with the earliest expiry date are consumed first.
BR-EXP-002 Before creating an export note, the system verifies that the total available quantity across all AVAILABLE batches is sufficient to fulfill every product in the order. If any product is short, the order is excluded from the "ready" list.
BR-EXP-003 If stock becomes insufficient during the actual export creation, the system throws an InventoryOutboundException and the entire transaction is rolled back.
BR-EXP-004 After a batch is allocated for export, its currentQuantity is immediately decremented and an EXPORT transaction is recorded in the inventory ledger.
BR-EXP-005 Upon successful export note creation, the associated StoreOrder status transitions to IN_TRANSIT.
BR-EXP-006 Manual Export: Allows the coordinator to manually select specific batches. The system validates that the selected batch has sufficient stock; if not, an exception is thrown.
BR-EXP-007 Surplus Export: Can be created without a StoreOrder (storeOrder = null). The export code is prefixed with PX-SUR-. Its initial status is immediately SHIPPED and it is never added to a delivery trip. Logged as SURPLUS_EXPORT in the ledger.
BR-EXP-008 An export note can only be cancelled if its status is not SHIPPED. Cancellation sets the status to CANCEL without physically deleting the record.
Delivery Management
(DEL)		 Hidden system logic Only export notes with storeOrder IS NOT NULL and status READY are eligible to be added to a delivery trip. Surplus exports are strictly blocked.
BR-DEL-001 A delivery trip can only be created by including export notes that are in READY status. After being assigned, each export note transitions to PLANNED.
BR-DEL-002 Surplus Export notes (storeOrder = null) are strictly prohibited from being added to any delivery trip. Attempting to do so throws an IllegalStateException.
BR-DEL-003 A delivery trip can only be started (IN_TRANSIT) if its current status is PLANNED. Upon start, actualStartDate is recorded and all linked export notes transition to SHIPPING.
BR-DEL-004 A delivery trip can only be cancelled if its current status is PLANNED (not yet departed). Cancelling after IN_TRANSIT is forbidden.
BR-DEL-005 When a delivery is cancelled, the system captures a permanent JSON snapshot of all linked export note details (store name, products, batch codes, quantities) before any state change. All export notes are restored to READY and unlinked from the trip.
BR-DEL-006 A delivery trip can only be completed if its status is IN_TRANSIT AND every linked StoreOrder has status DONE (store has confirmed receipt). Otherwise, an exception is thrown. Upon completion, all export notes transition to SHIPPED and actualEndDate is recorded.
